# relay restart recovery with live task clients

status: draft, pending independent review and final integration gates. no installed-service or deployment claim.

## scope and compatibility

server/relay restart recovery preserves opaque mail and transport progression while the **same plugin/agent processes stay alive**. plugins retain semantic task state, presentation evidence and pending outbox in RAM. this is at-least-once transport with stable protocol IDs, not exactly-once model/tool execution.

existing clients keep `volatile-v1`, `/api/task-relay/volatile-v1`, `/peer`, `/resolve-peer` and envelope protocol version 2. the historical wire name does not select storage. callers may use the existing name-or-UUID selector; fresh broker inspection resolves it to the canonical session UUID, which owns the registration. a reused name cannot access a different UUID's endpoint. clients never supply a recovered receive cursor or synthesize an endpoint.

server storage defaults to native SQLite. `WOLFPACK_TASK_RELAY_STORAGE=memory` explicitly selects the old weaker RAM-only server behavior; `WOLFPACK_TASK_RELAY_PROFILE` still accepts only `volatile-v1`. profile metadata identifies the store epoch and wire interface, not endpoint persistence, task readiness or execution. the removed WIP `restart-safe-v1` wire profile is not required or advertised. there is no automatic empty-store fallback.

baseline RAM-only clients can use the new server without upgrading. the focused client change adds truthful typed storage errors and cooldown diagnostics. new clients still speak to old servers; an old server restart still loses its epoch/mail and triggers the baseline truthful lost-state/rebind behavior.

plugin/agent-process restart recovery is **not implemented**. no endpoint SQLite/task journal, conversation/file identity bootstrap, transcript fsync, persistent presentation reservations, new Claude interrupted-MCP policy or endpoint-history garbage-collection protocol is included. session history does not restore active tasks or authorize replay.

## storage and retention

- the worker exclusively owns `restart-safe-v1.sqlite` under the configured relay root (normally `${WOLFPACK_DIR:-~/.wolfpack}/task-relay`). this is an internal storage filename/format, not wire negotiation. format `wolfpack-relay/restart-safe-v1`, SQLite `user_version=1`; no legacy data is read, migrated or deleted.
- owner-private directories (0700), files (0600), ownership, regular-file, hardlink and sidecar checks precede opening. SQLite EXCLUSIVE locking prevents concurrent owners. DELETE journals and FULL synchronization commit primary changes before acceptance/ACK responses or external forwarding.
- virgin SQLite initialization uses a reserved `.initializing` slot and native exclusive ownership, then atomic no-replace link/unlink publication plus directory fsync. a killed creation may resume only that unpublished slot or an exact owner-private, same-inode, two-link publication pair with valid format/origin and zero primary cells. arbitrary empty final files, corrupt slots and non-virgin hardlinks remain invalid and unchanged. the final connection reopens after link-count repair before any primary writes.
- primary state includes epoch, canonical session/generation registrations and their current/noncurrent status, endpoint cursors, peer aliases/epochs, receipts, immutable envelopes and forwarding progression. derived indexes rebuild after format/origin, integrity, checksums, relationship and bounded-usage validation. corrupt or unverifiable state blocks recovery instead of creating an empty epoch.
- reopening drops obsolete in-flight forwarding tokens, not immutable envelope/dedup identities. only the live endpoint reoffering its original operation drives another attempt; the owner never replays an interrupted mutation. unknown/rejected/expired forwarding reports uncertainty, not guessed acceptance.
- existing item/byte ceilings remain. new envelope admission has a seven-day horizon; terminal receipt tombstones remain eight days after completion. on receipt eviction, a fixed-size durable cutoff advances to the greatest evicted envelope `createdAt`. unseen envelopes at or below that cutoff fail `ENVELOPE_EXPIRED`, even after wall-clock rollback and reopen. retained receipts and accepted unacknowledged mail bypass new-admission checks; fresh timestamps above the cutoff do not inherit the previously observed wall-clock high. receipt creation timestamps and the cutoff are required recovery state; incomplete older draft journal state fails closed, without migration. accepted unacknowledged mail does not expire. SQLite page limits bound database growth.
- lease expiry, disconnection and broker unavailability are **not death**. the same current generation renews its existing endpoint/cursor after a lease gap. accepted mail and receipt/forward obligations prevent passive death-based retirement, including after broker death.
- on registration-capacity pressure, one bounded round-robin probe freshly inspects an expired, obligation-free registration's exact broker UUID. only authoritative death or `NOT_FOUND` can retire it. a conditional mutation check rejects a stale proof after concurrent renewal. unavailable, ambiguous or mismatched results retain state. later capacity retries continue probing; no new distributed garbage-collection protocol exists.
- a deliberate epochless fresh-generation connect after fresh canonical broker inspection creates an unrelated endpoint/cursor0. a predecessor with zero references is removed; a predecessor with only terminal transport receipts becomes noncurrent, preserving exact receipt IDs/digests/state/acceptance IDs/expiry and all original bounded charges. both registrations count against registration/metadata limits before replacement. mailbox or active/uncertain-in-flight forwarding references still reject replacement with `RELAY_RESET`; no obligations are deleted to make room.
- current/noncurrent identity, generation, obligations and capacity checks occur synchronously in the committed store mutation. restore rejects multiple current registrations per broker or nonterminal/empty retained predecessors. when the last terminal receipt expires, its noncurrent predecessor is pruned in the same mutation; current registrations are never swept this way. capacity can still reject a fresh generation explicitly with `RELAY_CAPACITY`.
- stale endpoint send/receive/ACK and retained-generation reactivation fail. normal bound clients include their saved epoch on reconnect; an epoch-bearing connect may only renew the current generation, even after predecessor records expire. an epochless request explicitly declares fresh lifetime semantics; after bounded history pruning, arbitrary reuse of an ancient generation string without a saved binding cannot be distinguished from another deliberate fresh connect. no unbounded generation tombstones or new wire negotiation are added. delayed target inspection revalidates the exact current endpoint/generation before renewal and cannot resurrect a predecessor.
- after normal wire/auth/trusted-peer/origin/epoch validation, an exact terminal receipt with acceptance evidence may confirm a duplicate without making its old target deliverable. immutable envelope digest/endpoints must match. changed, absent or expired receipts cannot admit mail to the old endpoint; terminal unconfirmed forwarding remains unknown without acceptance evidence. the same evidence recheck handles a mailbox ACK/replacement racing with awaited broker inspection.
- starting a fresh empty client after completed/fully transport-ACKed tasks is usable immediately, subject to normal capacity limits. this is not recovery of lost plugin RAM: predecessor tasks, outbox, cursors and ACK authority are never adopted. outstanding nonterminal transport obligations still block a fresh generation and require explicit operator handling, not automatic task replay.

## owner failures

failed owners stop and release their reservation only after confirmed termination. replacement reopens the same journal in single flight, with monotonic cooldowns of 1, 2, 4, 8, 16 and then 30 seconds. no uncertain mutation is replayed. only a successful connect from the current healthy owner resets recovery health; delayed committed replies remain truthful but cannot clear a later failure.

`RELAY_STORAGE_UNCERTAIN` is owner-fatal and potentially committed. `RELAY_STORAGE_BUSY` and `RELAY_STORAGE_UNAVAILABLE` report transient lock/open failures without takeover. `RELAY_STORAGE_INVALID` permanently blocks corrupt/unsupported/unverifiable storage for that facade lifetime. `RELAY_STORAGE_RECOVERY_BLOCKED` keeps the reservation when termination is unconfirmed. `RELAY_STORAGE_RECOVERING` rejects before admission with `retryAfterMs`. none authorizes a fresh task execution, new assignment, empty fallback or cursor resurrection.

## trust and verification limits

existing optional global JWT authentication, loopback/trusted Tailnet admission, canonical TLS origins, current topology and both relay epochs still apply. peers are assumed honest canonical machines, not signed task principals. do not expose these APIs through Funnel or an untrusted proxy.

focused tests exercise real server/worker process restart with an unchanged baseline RAM client, lost committed send/ACK responses, a real lease-length gap, stable epoch/endpoint/cursor progression, terminal result then parent ACK, and assignment/wake deduplication. trusted cross-host tests restart one and both actual relay host processes while clients remain alive. the network fixture maps canonical TLS origins to private loopback listeners; it does not claim physical two-host/Tailscale or power-loss coverage. native SQLite faults, exclusive locks, format/corruption refusal and obligation-aware retirement have separate focused checks. mixed-version failure tests select the exact baseline client/new server and new client/exact baseline server: real broker-unavailable errors and injected typed/unknown replies after committed acceptance/ACK retain RAM and stable retry IDs, with one production inbox assignment/wake. the new server also exercises a real native write fault/reopen with those same client objects alive; the memory-only old server cannot exercise that native fault. baseline clients report unfamiliar epochless storage failures as retryable `INVALID_RESPONSE`, not endpoint resets; newer clients retain typed storage diagnostics. final full suites remain parent-coordinated.
