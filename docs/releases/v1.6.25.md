# v1.6.25 — extensible session workspaces

Release candidate notes. Publication is pending PR review, CI and the physical-device checks required by [CONTRIBUTING](../../CONTRIBUTING.md), or an explicit release-specific exception. These notes do not claim that a tag, GitHub release or npm publication exists.

## Highlights

- Installable workspace widgets and terminal layout recipes through the public `wolfpack-bridge/extensions` SDK. Packages support local directories and exact npm versions, immutable snapshots, explicit browser-code trust, enable/disable, update, rollback and removal.
- Session-scoped, schema-validated agent documents with revision-checked writes. The Agent Context sample includes publication guidance as an optional Pi skill.
- The read-only Changes extension is extracted and prepared separately as `wolfpack-extension-changes`; it is **not published yet**, is a status panel rather than a diff editor, and has no filesystem watcher or Pi event hook.
- Independent widget placement and retained views, fixed docking targets, keyboard/mouse/pen placement, collapse-to-peek drawers and explicit pinning. Peeking does not resize terminals. Mobile widgets use a separate view with a return-to-terminal control.
- A full Sessions chooser before opening a terminal, compact All/Idle controls, Settings recovery for hidden widgets and improved keyboard/focus behavior.
- Server-owned machine display names remain separate from stable routing identities. Exact current-session identity is available to integrations without guessing by name.

## Installation and compatibility

- Existing sessions, terminal controllers and broker-owned PTYs remain independent of widget data and layout. A broker restart still terminates its sessions; installing or updating a widget does not require a broker restart.
- Widget packages are separately installed snapshots, not automatically enabled built-ins or live links to source. Remaining host examples and authoring instructions are under [`examples/extensions`](../../examples/extensions); Changes is maintained in its standalone package.
- Existing Agent Context document schema remains compatible. Schema-changing package updates still require explicit migration support; no migration is implied by this release.
- Changes reads the selected local session's launch project, not later shell `cd` destinations. Remote project status is unavailable rather than falling back to local data. Git reads are bounded and read-only, with no staging, commit, discard or arbitrary path/command API.
- The release includes the current main-branch installer ownership, atomic executable replacement, signed macOS broker provenance and configurable Pi task-worker discovery fixes from v1.6.24.
