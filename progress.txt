## Task 5: Create merge engine
- Extracted `git()` helper to shared `src/kobra-kai/git.ts` — used by both worktree.ts and merge.ts
- Updated `src/kobra-kai/worktree.ts` to import `git` from `./git.ts` instead of internal function
- Created `src/kobra-kai/merge.ts` with 2 exported functions:
  - `jsonMerge(base, ours, theirs)` — 3-way JSON merge: recurse objects (union of keys), concatenate+dedup arrays, scalars take theirs, type mismatch takes theirs
  - `mergeWave(projectDir, wave, dag)` — merges all task branches in a wave into an integration branch:
    - Creates `integrate/{project}/wave-{N}` from base (main for wave 0, prev integration for wave N)
    - Sorted deterministic merge order
    - Validates diffs against estimated_files, flags unexpected files (non-blocking)
    - Attempts `--no-ff` merge per task
    - On conflict: JSON files auto-resolved via `jsonMerge` using git index stages (:1:, :2:, :3:); non-JSON → abort + record
    - Sets wave.integration_branch and wave.status
    - Cleans up worktrees, returns to base branch
- Created `tests/unit/kobra-kai/merge.test.ts` — 17 tests, all passing:
  - jsonMerge: objects (union+recurse), arrays (concat+dedup), objects in arrays kept, scalars (theirs wins), nested objects, type mismatch, array vs object mismatch, null values

## Task 8: Create orchestration loop
- Created `src/kobra-kai/orchestrate.ts` with 9 exports:
  - `countTasksInContent(content)` — counts total/completed tasks in PLAN.md content (checkboxes + section headers)
  - `gatherProjectContext(projectDir)` — collects file tree (maxdepth 3, excluding node_modules/.git/*-wt-*), package.json summary, recent git log
  - `launchOrchestration(projectDir, dag, maxConcurrent)` — saves DAG + config, creates wave 0 worktrees, spawns task runners, registers in active set
  - `spawnWaveTasks(projectDir, wave, dag, maxConcurrent)` — gathers context, writes PLAN.md + .project-context in each worktree, spawns detached `bun task-runner.ts` (up to maxConcurrent), sets pid/status
  - `advanceOrchestration(projectDir)` — loads DAG + config, checks PIDs (process.kill signal 0), marks dead PIDs completed/failed based on PLAN.md status, spawns queued tasks when slots open, merges wave when all done, advances to next wave
  - `getOrchestrationStatus(projectDir)` — returns structured OrchestrationStatus from DAG state
  - `cancelOrchestration(projectDir)` — SIGTERM all in-progress PIDs, cleanup worktrees for non-merged waves, remove from active set
  - `startOrchestrationPoller(intervalMs)` / `stopOrchestrationPoller()` — setInterval-based polling of advanceOrchestration for all active orchestrations
  - `_getActiveOrchestrations()` — exposed for testing
- Module-level state: `activeOrchestrations: Set<string>`, `pollInterval: Timer | null`
- Created `tests/unit/kobra-kai/orchestrate.test.ts` — 22 tests, all passing:

  - advanceOrchestration: dead PIDs → completed when plan done, dead PIDs → failed when plan incomplete, spawns queued tasks when slots open, returns "waiting" when agents alive, triggers merge when wave done (single wave → completed), advances to next wave after merge, returns "completed" when all waves merged

## Task 9: Add API routes

  - `POST /api/kobra-kai/launch` — loads DAG from project, checks no active orchestration (409), launches with configurable maxConcurrent (default 3), starts poller
