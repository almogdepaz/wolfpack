# Broker

## When To Read This
Read for changes that affect local PTY lifecycle, reconnect fidelity, streaming order/recovery, or the broker wire contract. Do not treat it as the desktop/client implementation: the sibling `wolfpack` module is a client boundary and should be consulted only when changing cross-process behavior. Exact schemas and wire tags belong in `broker/src/protocol.rs` and `broker/src/codec.rs`.

## Ownership and authority
The broker is the authoritative local Unix-socket daemon for spawned PTYs, their process metadata, raw output sequence/replay, and terminal snapshots. It owns the Ghostty VT state through a narrow C FFI shim; clients must not reconstruct terminal state from output if a snapshot is needed. `SessionRouter` is authoritative for lifecycle, snapshot, and resize RPCs, while the server connection layer—not the router—owns per-connection subscriptions because they require writer-task state (`session_router.rs:67-114`, `server.rs:351-529`).

The transport assumes local-user authorization from the protected socket and parent directory. It deliberately passes accepted create fields (`cwd`, argv, environment) to the PTY subsystem; it is not a policy/authorization layer. Socket setup refuses to overwrite a non-socket or a live socket, removes only a demonstrably stale socket, and applies restrictive directory/socket permissions during bind (`server.rs:91-183`). Startup temporarily changes the process-wide umask around bind, so embed/start it only with that global side effect understood.

## Durable contracts
- **One output ordering domain per session.** The drainer must feed terminal state, increment `seq`, then publish the same sequence as an `OutputChunk`, under the terminal lock (`session.rs:552-594`). A snapshot's sequence therefore describes the highest incorporated output chunk, not merely an independently sampled timestamp. Do not move either side of this ordering or publish chunks that failed terminal ingestion.
- **Attach is an atomic replay/live cut.** `OutputBus::subscribe` takes sender and ring locks in the same ordering as publish: it attaches the receiver, captures retained chunks strictly after `since_seq`, and returns the corresponding watermark (`output_bus.rs:113-159`). This prevents a chunk from being both replayed and received live, or from being neither. The bounded ring is intentionally lossy; `replay_truncated` means a snapshot is required before trusting the returned slice.
- **An output frame may coalesce several chunks.** Server forwarding merges contiguous sequence chunks and stamps the frame with the *last* chunk sequence (`server.rs:532-548`). Consumers must treat it as ordered bytes ending at that sequence, rather than infer a one-frame/one-PTY-read relationship.
- **Subscription recovery is connection-local.** A successful subscribe response is queued before its replay/live output; re-subscribe replaces the old forwarder, and unsubscribe is idempotent but cannot retract frames already queued (`server.rs:381-531`). On broadcast lag, forwarding stops and queues `subscription_dropped` after accepted output frames, making that event an ordering barrier: resume from the last delivered sequence, honoring replay truncation (`server.rs:549-644`). Global lifecycle events are best-effort broadcast and can be lost to lag; they are notifications, not durable state.
- **Resize is a coupled transition.** Terminal resize occurs before PTY resize; a PTY failure rolls terminal state back, and session dimensions plus `session_resized`/`snapshot_invalidated` are committed/emitted only after both succeed (`session.rs:502-540`). The master lock serializes resize transitions. Preserve this coupling or metadata, PTY geometry, and snapshot geometry can diverge.
- **Exit has one lifecycle transition.** The drainer closes its bus on every EOF/error; read failure marks the session unavailable and emits exit once, while the child reaper records the eventual exit code without duplicating the event (`session.rs:552-718`). In the daemon, the registry's event reaper subsequently drops exited sessions and frees their name; callers may consequently see `unknown_session` rather than a permanently queryable dead record (`registry.rs:117-172`).

## Terminal-state / native boundary
`TerminalState` serializes all Ghostty handle access behind the session mutex and materializes snapshots from checked native metadata/row extraction (`terminal_state.rs:144-385`). Snapshot extraction is bounded at both C and Rust layers; C validates allocation/index/coordinate arithmetic and encodes cell text into a bounded buffer, while Rust retries only bounded buffer growth and validates every returned text range before conversion (`native/ghostty_vt_shim.c`, `terminal_state.rs:210-294,456-495`). Keep the C struct layouts and error-code mapping synchronized with `native/ghostty_vt_shim.h` and Rust FFI declarations.

Terminal semantics are intentionally Ghostty-authoritative: alt-screen excludes scrollback; scrollback limiting precedes optional reflow; reflow consumes `wrapped` markers and must preserve wide-character continuation cells (`terminal_state.rs:336-384,497-556`). Snapshot failures are surfaced as control-plane internal errors rather than returning partially materialized state (`session_router.rs:216-227`). The shim also fixes Wolfpack's ANSI palette and disables selected Ghostty capabilities, so changing it changes externally visible snapshots, not just an implementation detail (`native/ghostty_vt_shim.c:18-55`).

## Lifecycle and concurrency notes
Registry creation holds its mutex across name resolution and PTY spawn, so name reservation and insertion are atomic; `session_started` is emitted only after releasing that lock (`registry.rs:63-93`). Spawn uses a child guard that kills and waits on every post-spawn setup rollback path (`session.rs:143-188,221-340`). The process reaper uses a weak registry reference and performs a dead-session sweep after event-bus lag, preventing lost exit events from pinning names (`registry.rs:137-172`).

The socket writer has separate control and output queues and prioritizes control to keep responses/lifecycle traffic from sitting behind redraw bursts; output forwarding additionally has bounded local buffering and intentionally falls back to lag recovery under sustained pressure (`server.rs:26-33,321-644`). Do not collapse these queues without re-establishing response-before-subscribe-output and bounded-memory behavior.

- The build requires a verified target-specific Ghostty static bundle. `broker/build.rs` validates the manifest, repository lock content/hash, archive/header digests, and symbol policy before linking; update the bundle workflow and lock together rather than bypassing verification.
